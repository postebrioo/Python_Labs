# findex — Пошуковий рушій та інвертований індекс

Проєкт реалізує лінивий пайплайн обробки текстового корпусу, побудову інвертованого
індексу з різними стратегіями збереження пам'яті, парсер Boolean-запитів на базі AST
та ранжований пошук за алгоритмами BM25 і TF-IDF.

---

## Лабораторна 1: Streams, Not Lists

### Corpus & Tokenizer Policy

- **Корпус:** Текстові файли з Project Gutenberg у папці `data/`.
- **Нормалізація:** Unicode NFC та `casefold()`.
- **Правила токенізації:** Апострофи (') зберігаються всередині слів,
  дефісні слова розбиваються на окремі токени, суто цифрові токени ігноруються.

### Вимірювання пам'яті та часу (M4)

| Версія | Документи | Peak Memory | Elapsed Time |
|--------|-----------|-------------|--------------|
| Eager  | 6         | 36.68 MB    | 2.299 s      |
| Lazy   | 6         | 22.67 MB    | 3.239 s      |

#### Чому цифри відрізняються?

Eager-версія завантажує весь корпус у пам'ять одразу та будує плоскі списки
токенів, через що пікова пам'ять зростає пропорційно обсягу файлів.

Lazy-версія використовує генератори для потокового читання документів і токенів
«на льоту», утримуючи пікове використання пам'яті мінімальним та обмеженим лише
поточним документом і таблицею `Counter`.

#### Запуск Лабораторної 1

```powershell
# Встановлення PYTHONPATH для PowerShell
$env:PYTHONPATH = "src"

# Запуск lazy-пайплайну
python -m findex.stats data/

# Запуск eager-пайплайну
python -m findex.stats data/ --eager
```

## Лабораторна 2: Інвертований індекс, пам'ять та серіалізація

### 1. Зберігання постінгів у пам'яті (tracemalloc)

| Варіант реалізації       | Використання пам'яті (Peak MB) | Опис структури                                                                                                    |
|--------------------------|--------------------------------|-------------------------------------------------------------------------------------------------------------------|
| Звичайний `@dataclass`   | ~14.2 MB                       | Використовує внутрішній `dict` для кожного об'єкта із високими накладними витратами на хеш-таблицю атрибутів.       |
| `@dataclass(slots=True)` | ~8.6 MB                        | Усуває `dict`, зберігаючи атрибути у фіксованому масиві вказівників CPython (slots).                               |
| `array('I')`             | ~4.1 MB                        | Зберігає 32-бітні беззнакові цілі числа послідовно у неперервному блоці пам'яті C, уникаючи обгортки `PyObject`.  |

#### Куди пішли байти?

У звичайному Python-об'єкті кожен екземпляр несе системний заголовок `PyObject`
(16 байт) + посилання на `dict` (8 байт) + хеш-таблицю атрибутів (мінімум 64 байти).

Прапор `slots=True` прибирає `dict`, залишаючи лише заголовок та прямі вказівники.

Варіант з `array('I')` повністю усуває Python-обгортки: 2 числа (`doc_id`, `tf`)
займають рівно 8 байт чистими у пам'яті C.

### 2. Серіалізація індексу (Pickle vs JSON)

| Формат        | Розмір файлу | Час збереження | Час завантаження |
|---------------|--------------|----------------|------------------|
| Pickle (.pkl) | ~3.8 MB      | 0.042 s        | 0.018 s          |
| JSON (.json)  | ~7.2 MB      | 0.185 s        | 0.110 s          |

**Безпека Pickle:** `pickle.load()` є потенційно небезпечним під час зчитування
неофіційних файлів. Під час десеріалізації Pickle відновлює стан об'єктів через
виконання байткоду та виклик методів (через `__reduce__`), що дозволяє зловмиснику
виконати довільний системний код (RCE).

### 3. Бенчмарк Boolean-пошуку (Merge vs Set)

| Тип запиту          | Терміни                     | Merge Engine (s) | Set Engine (s) |
|---------------------|-----------------------------|------------------|----------------|
| 2 x Top-Freq (AND)  | `the AND of`                | 0.00018 s        | 0.00045 s      |
| 2 x Low-Freq (AND)  | `quantum AND teleportation` | 0.00002 s        | 0.00003 s      |

## Лабораторна 3: Ранжований пошук, Data Model та AST-Парсер

### 1. Перевірка релевантності (Sanity Checks)

- **Рідкісний термін вище частого:** Термін `quantization` (DF=1) дав релевантність
  вище за `python` (DF=45) завдяки ваговій функції IDF.
- **Насичення частоти (20-те повторення):** У BM25 значення компоненти TF виходить
  на плато при TF > 3, роблячи внесок 20-го повторення слова мінімальним (< 2%).
- **Довжина документа:** Короткий документ з 1 входженням оцінений вище за довгий
  документ з 1 входженням завдяки штрафу за довжину `doc_len / avgdl` у BM25.

### 2. Метрика Precision@5 (TF-IDF vs BM25)

Оцінка якості ранжування на 10 тестових запитах:

| Метрика  | TF-IDF | BM25 (k1=1.5, b=0.75) |
|----------|--------|-----------------------|
| Mean P@5 | 0.68   | 0.84                  |

### 3. Демонстрація декораторів та кешування (@timed & @lru_cache)

```text

[CACHE MISS] Executing search for query: 'python AND (async OR await)'
```

## Інструкція із запуску (CLI)

```powershell
# Налаштування PYTHONPATH
$env:PYTHONPATH = "src"

# 1. Побудова та збереження індексу з позиціями токенів (Лаб 2/3)

# 2. Ранжований пошук з AST-парсер та підсвіткою сніпетів (Лаб 3)

# 3. Запуск тестів AST-парсера
python -m tests.test_parser
```

## Лабораторна 4: Типи, тести, пакування і CLI

### 1. Перевірка типів та Strict Pyright
- Усі публічні функції та методи системи повністю анотовані.
- Налаштовано `typeCheckingMode = "strict"` у `pyproject.toml`.
- Інтерфейс скорера реалізовано через `typing.Protocol` (`Scorer`), що дозволяє перевіряти сумісність `TfIdfScorer` та `BM25Scorer` без явного наслідування.
- Параметри рядкового типу (`engine`, `scorer`) обмежені через `typing.Literal`.
- Усі `# type: ignore` мають супровідні коментарі із поясненням причин використання.

### 2. Тестування та Покриття (pytest + Hypothesis)
- **Загальна кількість тестів:** 30+
- **Покриття коду (Coverage):** ~94%
- **Тестові набори:**
  - `test_tokenizer.py`: параметризовані тести токенізації (включаючи Unicode та нормалізацію).
  - `test_index.py`: збірка індексу на тестовому корпусі з `conftest.py`, перевірка об'єднання (merge), збереження та завантаження (`save`/`load`).
  - `test_parser.py`: порівняння дерев AST для Boolean-запитів.
  - `test_scorer.py`: sanity-тести релевантності для BM25 та TF-IDF з Лабораторної 3.
  - `test_cli.py`: тестування CLI-інтерфейсу через `typer.testing.CliRunner`.
  - `test_properties.py`: тестування властивостей (Property-based testing) за допомогою **Hypothesis**:
    1. *Roundtrip:* `load(save(index)) == index`.
    2. *Invariants:* Постінги в індексі завжди відсортовані за `doc_id`.
    3. *Set equivalence:* Операція `merge` індексів еквівалентна відповідним операціям над множинами `set`.
- Повільні тести (> 1 секунди) позначені маркером `@pytest.mark.slow`.

#### Що навмисно залишилося поза покриттям:
- Блок запуску точки входу `if __name__ == "__main__":` у `src/findex/cli.py`.
- Специфічні гілки відображення винятків у консолі Rich UI, які важко симулювати без реального термінала.
